# 失败矩阵

| 现象 | 已证实原因 | 未证实项 | 应等待/应发送 | 下一步证据 |
| --- | --- | --- | --- | --- |
| 地下城不在列表 | `unlocks` 与 `showUnlocks` 的交集不含目标；操作台返回“当前不可扫荡” | 服务端是否还有隐藏资格字段 | 不发送 `19642` | 保存同一登录窗口的完整 `Game_data` |
| 原生没有扫荡按钮 | `compeleted[dungeon_id]` 为假；按钮由 `CheckCompleteDungeon` 控制 | `compeleted` 与 `unlocks` 的服务端更新时序 | 不发送扫荡 | 补抓通关后 `19618/19620` 状态推送 |
| 今日挑战次数达到配置上限 | `challengeTimes[id] >= dungeon.limit`；表中普通地下城 `limit=3` | 是否按自然日、区服时区或赛季重置 | 不发送扫荡 | 记录跨日/重置后的 `Game_data` |
| 扫荡响应 `ret=3` | 原生中文资源 `dungeon.sweepRet3` 定义为“无扫荡次数” | `Game_data.sweeps` 与该次数的确切关系；当前样本未携带 field 34 | 自动任务记录为跳过，不自动重发 | 保存带 field 34 的 `Game_data` 与同一操作窗口响应 |
| 扫荡响应 `ret=4` | 运行时确实收到 `19642` 入站 `ret=4`（52 次） | `ret=4` 的业务文案/原因；不能从非零码单独推断 | 不自动重发；保留错误码 | 获取原生提示映射或同操作窗口日志 |
| 消耗品不足 | 原生入口检查 `row.consume`，普通表为 `901,1` | 操作台未在本地检查背包数量，服务端拒绝码未知 | 等待 `19642`；失败即终止该次尝试 | 补采库存通知与拒绝帧 |
| 装备容量不足 | 原生入口检查 `getEquipFreeCapacity()` | 扫荡是否实际产生装备、服务端是否独立校验 | 不发送 | 记录容量与拒绝码 |
| 扫荡成功但没有继续抽取 | 原生 UI 依赖 `drawtimes < totaltimes` 和 `19626` 信息查询；操作台直接进入 `19604` | `19618` 推送与 `19642` 响应的先后竞争 | 原生等待状态刷新；操作台等待/校验 `19604` | 同一原生窗口抓取 `19642,19618,19626` |
| `Dun_treasure_info` 返回非零 | `OnTreasureInfo` 只提示 `label.dungeon.gettreasureinfoerror` | 各 `ret` 具体含义 | 不发送 `19604` | 获取宝库面板的错误码映射 |
| `Dun_start_draw` 返回非零 | `DungeonDrawRejected` 保留 `ret`；不更新次数 | 是否已产生部分奖励 | 不重发；检查连接和最终状态 | 对应响应与后续库存帧 |
| 抽取响应地下城 ID 不匹配 | 本地客户端显式校验 `response.dungeon_id == requested_id` | 服务端是否可能串行返回旧请求 | 丢弃并标记协议错误 | 保留完整序列号和会话 ID |
| 抽取成功但无库存通知 | 通知是异步副作用，服务器可能在短连接关闭前未送达 | 奖励是否已落袋不能由本地确认 | 以 `dropids/prob` 作为展示回退，不宣称背包已同步 | 延长只读监听或刷新 `Game_data`/Storage |
| 收到非 71 的库存通知 | `DungeonSweepClient` 忽略非 `DUN_DRAW` 来源 | 是否属于同一动作的其它奖励源 | 继续等待目标来源，不把其它来源计入地下城奖励 | 解析 source 枚举和关联序列 |
| 日常任务 107 动作后仍未完成 | 本地动作返回不覆盖服务端状态；前后 `19700` 未形成 `false -> true` | 进度上报是否由玩法推送延迟完成 | 再查状态，不盲目追加扫荡 | 记录 `Game_data` field 12、`19700` 前后状态 |
| `19702` 任务积分领取失败 | 响应 `ret != 0` 时 `claim_available` 立即抛错 | 任务是否已部分入账 | 不重复请求；刷新日常状态 | 获取该任务的错误码文案 |
| 日活阈值未达到 | 只为 `reward.score <= activity_score` 的配置构造请求 | 是否有特权/活动加成影响分数 | 不发送 `19704` | 记录最终任务分数与配置版本 |
| `19704` 重复领取 | 奖励 ID 已存在于 `daily_reward_ids`/`weekly_reward_ids` | 服务端幂等行为 | 不重复请求 | 对比前后 `19700` |
| 取消批次 | `DailyActionRunner` 在动作间或动作后检测到 stop | 已发请求的服务端最终结果 | 不再发后续动作；取消时只刷新状态 | 记录取消点和晚到响应 |
| WebSocket 超时、断线或 kickout | 通用会话处理器抛出超时/连接/kickout 异常 | 是否支持原生重连恢复上述阶段 | 不自动重发业务包 | 只读重连采集，确认是否有原生恢复发送点 |
