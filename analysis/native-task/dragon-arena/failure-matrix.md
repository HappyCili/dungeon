# 失败矩阵

| 现象 | 已证实原因 | 应等待/应发送 | UI 结果 |
| --- | --- | --- | --- |
| `21104 ret != 0` 且没有 `18002` | 当前候选被服务端拒绝，未进入战斗；`challenge=false` 仅表示未胜利通过，不保证即时可战 | 记录该序号，发送 `21100` 刷新并继续其他候选 | 显示 `ret` 和序号，不报“未收到结算” |
| 本地候选轮次耗尽，但 `21100` 仍含 `challenge=false` | 本地去重不等于服务端候选耗尽 | 以 `robot_id` 而非列表序号去重；整轮均被拒绝后等待 750 ms，再重新尝试，禁止发送 `21102` | 显示服务端剩余人数与重试等待 |
| `21100` 刷新后候选重排 | 列表序号不稳定，同一位置可能是另一名机器人 | 保留已拒绝的 `robot_id`，重新计算其当前序号 | 不跳过新候选，也不重复请求已拒绝机器人 |
| 服务端候选已耗尽后 `21102 ret != 0` | 服务端暂拒绝重新匹配 | 10 秒后重试 `21102` | 显示匹配 `ret`，保持作业运行 |
| 已收到 `18002/18012` 后未收到 `21106` | 结算尚未到达或链路中断 | 等待至战斗超时 | 显示“未收到服务端战斗结算” |
| 已收到 `21106` 后胜利选择未完成 | 仅抉择步骤未完成 | 等待 `21108` | 保留战斗结果与抉择状态 |
