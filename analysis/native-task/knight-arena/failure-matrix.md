# 失败矩阵

| 阶段 | 观测或判定 | 处理 | 是否计为完成 | 证据 |
| --- | --- | --- | --- | --- |
| 竞技场入口 | `seasonopen=false` | 停止，不尝试挑战 | 否 | 静态、项目实现 |
| 每日奖励 | `getdailyreward=true` | 不重复领取 | 不适用 | 静态 |
| 每日奖励 | `19814` 返回非零 `ret` | 保留失败；不要仅根据原生 UI handler 的本地赋值断言服务器已发奖 | 不适用 | 静态；成功样本缺失 |
| 免费次数 | `remaining==0` | 跳过普通竞技场免费挑战 | 否 | 项目实现 |
| 免费次数 | 每日免费上限与 `refreshnum` 或红点状态混淆 | 仅使用已确认上限 `5` 与 `challengenum` 计算预算；刷新次数和 UI 红点不参与限额 | 否 | 静态、项目实现、业务确认 |
| 选人 | 候选为空或全被尝试 | 允许时发送 `19808` 刷新；否则结束 | 否 | 项目实现 |
| 刷新对手 | `19808.ret!=0` 或返回空列表 | 停止本轮，保留服务端 `ret` | 否 | 静态、运行时 |
| 进攻编队 | 槽位 4 不存在/为空 | 不构造 `18010` | 否 | 项目实现、测试 |
| 编队同步 | `15016` 非零返回、缺少 `15014` 或超时 | 中止本轮 | 否 | 项目实现 |
| 挑战 | `19810.ret!=0` | 不发送 `18010`；不占用自动任务免费预算，可尝试当前列表其他候选；当前原生对 `ret<=13` 显示具体标签，其余显示通用错误 | 否 | 静态、运行时、项目实现 |
| 挑战 | `18002` 早于 `19810` 响应 | 缓存 `Battle_info`，继续等待/处理，不重复发挑战 | 否，直至结算 | 项目实现 |
| 备战 | `18002.ret!=0`、无战斗 ID、无敌方站位 | 终止本轮 | 否 | 项目实现 |
| 备战恢复 | 仅有 `Battle_info(battle_type=5)` | 仅解除本地备战屏障；不自动发 `18010` | 否 | 恢复逻辑 |
| 开战 | `18012.ret!=0` | 终止本轮，不等 `19818`；自动任务不再换下一个对手，以避免在已接受挑战后额外消耗免费次数 | 否 | 运行时 `ret=7`、项目实现、测试 |
| 战斗中 | 连接关闭或战斗超时 | 记录未完成原因；可由恢复模块在有运行中证据时续接 | 否 | 项目实现、恢复逻辑 |
| 结算 | 未收到 `19818` | 即使见到 `18090` 也保持未结算 | 否 | 静态、项目实现 |
| 结算 | `19818.win=0` | 更新积分并记录失败 | 是 | 静态、项目实现 |
| 结算 | `19818.win=1 && opponenttype=0` | 更新积分，并将当前候选标记为已胜 | 是 | 静态 |

本地抓包第 30 帧的 `18012.ret=7` 和第 32 至 58 帧的 `19810.ret=9` 都是可复现的失败分支；原生资源中未找到这两个返回码的文本含义映射，因此文档不把它们命名为具体业务错误。
