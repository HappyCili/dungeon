# 活动签到：状态机

```text
共享 GameSession 已就绪
  -> 读取登录时已保存的 Game_data
  -> 解析 signinData.acts
  -> 筛选 ticket.status == 1 且 todaySigned == false
  -> 对每个候选活动发送 21000 { id }
  -> 等待 21000 结果
  -> ret == 0：记录领取成功
  -> ret != 0：记录跳过，继续下一个候选
  -> 汇总结果
```

原生客户端在登录 `Game_data` 回调中保存完整签到状态；领取成功后以 `21000` 的 `act` 字段更新对应活动。当前实现保持同一共享会话，避免额外登录与无回包的全量同步等待。

原生 UI 还会按 `activity_signin` 配置判断是否已满档及奖励票券细则。当前工作区没有可复用的活动配置加载器，因此自动任务只采用已验证的服务端状态筛选，最终领取资格以 `21000.ret` 为准。
